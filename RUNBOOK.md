# Compliance evidence vault runbook

Authoritative sources are immutable versions carrying publisher, HTTPS URI, jurisdiction, effective/retrieval dates, version, content digest, and provenance. Policies are separately versioned and move through author, reviewer, and approver stages with accountable owners, linked evidence, segregation of duties, scenario evaluations, and append-only decisions. Release requires validated citations plus obligations with owners, deadlines when required, and bounded risk ratings. Legal holds override retention deletion; audit exports must be access-controlled, integrity checked, and redacted for the recipient.

Install dependencies explicitly and run `./start.sh check`. Back up PostgreSQL, then apply `ALLOW_SCHEMA_MIGRATION=1 ./start.sh migrate`. Build before `./start.sh start`; startup never installs, seeds, migrates, creates databases, or kills processes. Monitor source freshness/change queues, overdue obligations, failed evaluations, unauthorized access, release attempts, and legal-hold changes. Preserve decisions and provenance through backup/restore.

The application implements OIDC authorization code with PKCE, discovery, state/nonce validation, JWKS signature verification, issuer/audience checks and deny-by-default role/tenant claim mapping. Register the callback, store client credentials in the deployment secret manager, approve `OIDC_ROLE_MAP_JSON` and `OIDC_TENANT_CLAIM`, enforce MFA at the IdP, and test login/logout and tenant isolation before production release. Regulatory/contract source licenses and connector credentials, counsel interpretation, jurisdiction coverage, records/retention policy, legal-hold procedure, security assessment, recipient-specific audit-export acceptance, production-environment recovery testing, and representative compliance-user validation remain external gates. AI output remains advisory until the governed release gates pass.
